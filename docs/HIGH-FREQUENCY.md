# 高周波の音響通信（実験）

Android 0.6.4のSignalでは、1.8 kHzに加えて18・19・20・21・22 kHzを選択できます。既定値は1.8 kHzです。高周波を選ぶと実験設定が有効になり、送信・受信・ACKが同じ周波数を使います。2台の設定を合わせてから開始してください。開始中は周波数を変更できず、停止後に変更できます。

周波数の上限は22 kHz、かつ実際のAudioContextサンプルレートの半分未満です。AudioWorkletの実レートを検出器に渡します。高周波はマイク上で小さな振幅になるため、専用の感度を使います。復号候補はCRC検証し、不正な本文を推論入力にしません。別端末から受信文字やPCMをコピーする仕組みはありません。

18〜20 kHzは人によって聞こえます。高周波を選択しただけでは「無音」や通信成功を意味しません。

## 検証

- 44.1/48 kHzで、1.8/18/19/20/21/22 kHzの合成PCMを試験。日本語本文、ACK、ヘッダー、雑音、減衰、15 Hzの周波数差、CRC不一致、背景雑音のみを検証します。
- UIは初期値、6候補、保存、切替禁止、停止・背景移行、画面幅をブラウザーの偽マイクで検証します。このテストは実機音響の証拠ではありません。
- 実機の測定結果は以下に追記します。採用基準を満たす帯域が確定するまで、1.8 kHzを標準として使用してください。

## 2026-09-13の実機結果

Pixel 9aとPixel 7を横に並べ、両端末のメディア音量を25/25、20 WPM、アプリ音量20%にして測定しました。両端末のAudioContextと録音設定は48 kHz、1チャンネルで、エコー除去・雑音抑制・自動利得は無効でした。生のマイク録音は保存していません。

短いVVV信号は18・19・20 kHzで両方向3/3を検出し、クリッピングはありませんでした。候補選択は悪い側の雑音余裕から18 kHzと19 kHzになりました。21・22 kHzはPixel 9aからPixel 7の方向で復元できなかったため候補外です。

18 kHzの本文・ACK試験は、Pixel 9aからPixel 7が7/7初回配送、Pixel 7からPixel 9aが6/6配送、そのうち初回3/6でした。本文とACK「じゅしんしました」はすべて一致し、重複配送はありませんでした。7往復目の途中でPixel 9aが切断されたため、10回の試験は未完了です。既に逆方向の初回9/10以上を満たせないため、18 kHzは採用基準不合格です。

再接続後の19 kHz本文・ACK試験は、1回目のPixel 9aからPixel 7で本文を2回とも復元できず、Pixel 7からPixel 9aでは本文1件を復元しましたがACKを2回とも送信側で復元できませんでした。両方向とも再送込み10/10が不可能になった時点で、不要な高周波音を避けるため残りを打ち切りました。19 kHzも不合格です。合格候補がないため、実Gemma 10ターン試験には進んでいません。

18 kHzの音は、配置と端末音量を変更する前にユーザーから「小さく聞こえる」と報告されました。変更後の聞こえ方は未確認です。18〜22 kHzの全候補が実機採用基準を満たさなかったため、推奨できる高周波帯域はなく、標準値は1.8 kHzのままです。

## 実機試験の再現

同じデバッグAPKを入れた2台を指定し、Signal画面を前面に保ちます。ADBはテストの操作と読取にだけ使い、信号そのものはスピーカーから相手のマイクへ送ります。生のマイク録音は保存しません。

```sh
python tools/test_high_frequency_devices.py --a SERIAL_A --b SERIAL_B --output test-results/high-frequency
python tools/test_high_frequency_roundtrip.py --a SERIAL_A --b SERIAL_B --frequency FREQUENCY_HZ --volume APP_VOLUME --output test-results/high-frequency-roundtrip
python tools/test_high_frequency_conversation.py --a SERIAL_A --b SERIAL_B --frequency FREQUENCY_HZ --volume APP_VOLUME --output test-results/high-frequency-conversation
```

帯域測定は20 WPMで各方向3回、音量20%から始め、条件を満たさなければ40%、60%を試します。本番と同じ6つの検出条件を使い、各方向2/3以上でいずれかの受信器がVVVを検出し、受信振幅が0.0002以上、測定した雑音との差が10 dB以上、クリッピングなしを候補条件とします。両方向を満たした帯域から、最小受信余裕が大きい順に最大2候補を選びます。同点なら高い帯域を優先します。

本文試験は各方向10回。初回9/10以上、再送込み10/10、ACK内容一致、重複配送なしを要求します。合格した帯域だけで実Gemmaの10ターン会話を確認します。全候補が不合格なら、推奨高周波なしとして1.8 kHzを維持します。
