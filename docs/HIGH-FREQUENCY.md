# 高周波の音響通信（実験）

Android 0.6.4のSignalでは、1.8 kHzに加えて18・19・20・21・22 kHzを選択できます。既定値は1.8 kHzです。高周波を選ぶと実験設定が有効になり、送信・受信・ACKが同じ周波数を使います。2台の設定を合わせてから開始してください。開始中は周波数を変更できず、停止後に変更できます。

周波数の上限は22 kHz、かつ実際のAudioContextサンプルレートの半分未満です。AudioWorkletの実レートを検出器に渡します。高周波はマイク上で小さな振幅になるため、専用の感度を使います。復号候補はCRC検証し、不正な本文を推論入力にしません。別端末から受信文字やPCMをコピーする仕組みはありません。

18〜20 kHzは人によって聞こえます。高周波を選択しただけでは「無音」や通信成功を意味しません。

## 検証

- 44.1/48 kHzで、1.8/18/19/20/21/22 kHzの合成PCMを試験。日本語本文、ACK、ヘッダー、雑音、減衰、15 Hzの周波数差、CRC不一致、背景雑音のみを検証します。
- UIは初期値、6候補、保存、切替禁止、停止・背景移行、画面幅をブラウザーの偽マイクで検証します。このテストは実機音響の証拠ではありません。
- 実機の測定結果は以下に追記します。採用基準を満たす帯域が確定するまで、1.8 kHzを標準として使用してください。

## 実機試験の再現

同じデバッグAPKを入れた2台を指定し、Signal画面を前面に保ちます。ADBはテストの操作と読取にだけ使い、信号そのものはスピーカーから相手のマイクへ送ります。生のマイク録音は保存しません。

```sh
python tools/test_high_frequency_devices.py --a SERIAL_A --b SERIAL_B --output test-results/high-frequency
python tools/test_high_frequency_roundtrip.py --a SERIAL_A --b SERIAL_B --frequency FREQUENCY_HZ --volume APP_VOLUME --output test-results/high-frequency-roundtrip
```

帯域測定は20 WPMで各方向3回、音量20%から始め、条件を満たさなければ40%、60%を試します。各方向2/3以上でVVVを検出し、受信振幅が0.0002以上、測定した雑音との差が10 dB以上、クリッピングなしを候補条件とします。両方向を満たした帯域から、最小受信余裕が大きい順に最大2候補を選びます。同点なら高い帯域を優先します。

本文試験は各方向10回。初回9/10以上、再送込み10/10、ACK内容一致、重複配送なしを要求します。合格した帯域だけで実Gemmaの10ターン会話を確認します。全候補が不合格なら、推奨高周波なしとして1.8 kHzを維持します。
