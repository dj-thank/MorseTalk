# 実機の受け入れテスト — 未実施チェックリスト

この一覧は**合格の記録ではありません**。２台の物理端末で実施して、OS/端末/音声サービスの版・設定・結果を記入します。自動テストが通っても、実機確認の代わりにはしません。

## Gate A: ビルドと起動

- [ ] Android: AGP 8.9.2 / Gradle 8.11.1、`assembleDebug` と `lintDebug` が成功。APKが生成される。
- [ ] Android: 端末へのインストール・初回起動・回転・システムバー・キーボードで操作部が隠れない。
- [ ] Windows: ZIPをUnicode/空白を含むフォルダーに展開し、非管理者で`Start-Windows.cmd`が起動。
- [ ] Windows: ポート使用中・音声エンジンなし・Pythonなしを、誤った成功表示なしで説明する。
- [ ] ローカルページに外部通信がなく、Androidに外部ページを表示させられない。

## Gate B: 音声機能単体

- [ ] マイク許可・拒否・拒否後の再許可で、画面が固まらず再開できる。
- [ ] 日本語/英語を短く録音し、正しい言語データを選び、文字へ変換できる。
- [ ] 認識結果は送信前に編集でき、無言・認識失敗を自動送信しない。
- [ ] ネットワークを切った状態で認識とTTSを試す。未導入モデルは説明して停止する。
- [ ] 20秒制限、録音終了、すべて停止、着信、ロック、ホーム画面、別アプリへの切替でマイクが解放される。
- [ ] 読み上げ終了・停止・失敗後、受信を必要に応じて再開し、自分の声を再送しない。

## Gate C: ２台での実音響テスト

最初はACKオフ、40 WPM・700 Hz・コード0000、「はい」。受信側を先に開始。音が大きすぎる場合は下げ、距離を近づけます。

- [ ] Windows→Android、Android→Windows、Android→Androidで日本語が完全一致。
- [ ] 欧文HELLO、和文アリガトウがそれぞれ指定方式で受信できる。
- [ ] 通信コード違い・方式違い・大きく違う速度で、誤ったMT1日本語を読み上げない。
- [ ] 音の途中停止・物音・端末移動・他の音声で破損したMT1はCRC失敗として拒否。
- [ ] ACKオン時に確認が届く。受信側の自動応答オフでは一度だけ再送し、以後は不明と表示。
- [ ] 再送を重複表示/重複読み上げせず、再送された確認要求には必要に応じてACKを返す。
- [ ] ACK待ちの停止、すぐ新しい送信、受信中の読み上げ、相手から別の文が来る場合に音声所有が競合しない。
- [ ] 連続10往復でマイクや音源の数、メモリー使用量、履歴量が際限なく増えない。
