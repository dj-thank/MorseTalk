# MorseTalk 0.3.1 — 操作・状態表示・受信制御の改善

Gemma 4 E2B（Android LiteRT-LM 0.17.0、Windows Ollama）の実装を維持しています。
モデル・量子化・推論ライブラリの変更による高速化を主張する更新ではありません。

## 使い始める

準備カードでモデル・許可・A/B設定を確認します。Androidでモデルがない場合は「モデルの入手先」からGoogleの説明を外部ブラウザで開きます。自動ダウンロードやクラウド切替は行いません。
取り込み中はコピー済み容量と、全体サイズが分かる場合に限って割合を表示します。全体サイズ不明時に架空の進捗率は表示しません。空き容量は端末の値です。
ダウンロードで名前に「(1)」などが付いても同じE2Bの .litertlm を選べます。別モデル名、GGUF、パス指定は受け付けません。ファイルの実行可能性や出所を名前だけで保証するものではありません。

## 2台の接続コード

「接続コードで２台の設定を揃える」を開きます。Aで「新しいセッション」→「コピー」、Bで貼り付け→「このコードを適用」。A/Bの役割は手動で別々に設定してください。

```text
MT2|0000|AABBCCDD|120|8|180
```

順に通信コード・セッション・速度・会話ターン上限・応答バイト上限です。
すべてを検査してから反映します。不正な項目があれば一部だけ書き換えません。
AIの接続先、モデル、役割、許可、会話本文は共有しません。コードを適用してもマイクやAIを自動で開始しません。
接続コードは文字による設定共有であり、無線ペアリングや相手認証・暗号鍵ではありません。
初回は両端120WPMから試し、同じ会話上限を設定してください。

## 会話と停止

話題のひな型で作業相談・アイデア出し・短い接続確認を選べます。内容は編集可能で、選択だけでは推論を開始しません。
画面内ジャンプと固定の停止バーから、長い画面でも停止できます。実行の経過時間・到達ターン・再送回数を表示します。
経過時間は準備や待機を含む現在の操作の時間であり、片道のモールス音の長さやGemma単体の推論性能ではありません。
停止直後もネイティブ処理がまだ終了していなければ、モデル状態欄が更新されるまで他の処理を受け付けません。
ネイティブ初期化を危険な強制終了はしません。遅れて返った中断済み操作のエラーが、新しい操作をキャンセル・上書きしないようにしました。

## 診断ログ

停止後、診断欄の「検証ログを保存」でJSONを端末内に保存します。既定は会話本文と生のエラーメッセージを除いた記録です。本文が必要なときだけチェックを入れます。
設定済みAIエンドポイント、認証トークン、許可状態は出力しません。本文を含めればそこに個人情報が含まれる可能性があります。
ログはメモリ内最大400イベント。古いイベントが落ちた件数も出力します。サーバーへの自動送信やlocalStorageへの自動保存はありません。
「表示を消去」はこのログと表示を消します。実行中の設定変更やログ保存・消去を無効にし、実行記録が途中で混ざらないようにしています。

## 受信制御・表示専用ページ

同じフレームの重複受信は、予約中のACKを共有します。完了後の再送には再びACKを返します。
ACKキューを最大4件に制限し、混雑で受け付けなかったデータは連番を進めません。再送時に処理できます。会話本文の圧縮形式とMT2の互換性は維持しています。
Androidでライセンス本文が開けなかった問題を修正しました。表示専用ページにはネイティブ操作の権限を与えません。同一AIページ内のジャンプは橋渡しの識別を維持します。

## 検証と限界

配布APKとテストAPKを一度だけビルドし、AndroidのHTTP／端末内Gemma検証ジョブが同じ成果物を取得してハッシュ照合後にインストールします。別ジョブで再ビルドした同一ソースだけを根拠にしていません。

Node、Python、実ブラウザの操作、Androidエミュレーター、実Gemmaの各検証は `.github/workflows/verification.yml` で別々に実行します。
`tools/test_ai_ui.py` のネイティブ・AIはテストダブルです。モデル取り込み進捗の表示や停止競合を検証しますが、実端末の2.59GBファイル選択・コピーが成功したという意味ではありません。
Androidのネイティブ推論と、Ollamaを使った実時間仮想音声は別々の試験です。物理2台のスピーカー・マイク、雑音・反響・距離、Pixel9a/GPU、実音声ASR/TTSの検証を代替しません。
APKはデバッグ署名、モデルは別途取り込み。本番公開用署名や暗号化・相手認証はありません。

## 画面遷移の最終確認

別のCI実行でライセンス検証が失敗しました。遷移先の本文と同じ文言が元画面のリンクにもあり、到着前に検証を進められる判定を修正しました。実際の移動先URLと文書の準備完了を両方確認します。
加えて、遅れて完了するネイティブ処理の結果を表示専用ページへ送らない制限をJava側とJavaScript実行時の両方に設けました。ライセンス画面に故意に遅延応答を注入する回帰テストと、AI画面への復帰を3回繰り返す検証を追加しました。WebViewの録音許可とファイル選択も操作可能ページに限定しています。
これは遷移制御と回帰確認の改善であり、元の失敗が外部攻撃を証明したという意味ではありません。
