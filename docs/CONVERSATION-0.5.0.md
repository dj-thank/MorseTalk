# MorseTalk 0.5.0: Gemma同士の多話題会話

## 操作

「話題を選ぶ」で日常、音楽、料理、旅、科学、AI、学び、ゲーム、創作、哲学を選択できます。あくまで編集可能な最初の話題で、AIの返答を固定する台本ではありません。「自分で入力」で任意の話題も使えます。
「会話のスタイル」は自然な雑談／アイデアを広げる／別の視点で考える／質問して深掘り。AとBには補完する役割を与えます。2台ではそれぞれ設定してください。QRには会話の目的・スタイル・本文を含めない従来仕様を維持しています。

モデルを読み込み、AI処理を明示許可してから、B受信待機→A受信待機→Aから開始します。B側は直前に受信した話題を優先します。AndroidはGemma 4 E2Bの端末内LiteRT-LM、Windowsは設定済みローカルOllamaを使い、モデルやクラウドの自動切替はありません。

「1台でAI同士の会話を試す」では、実際に設定したモデルを2役で使い、両者の発言と受信確認をPCMモールス化・復号して受け渡します。最大8ターン、音は鳴らさず数値計算するモードです。独立した2台や実時間音響の検証ではありません。既存の「実AI×2 · PCM仮想経路」と同じ処理への入口です。

## 人が会話中に話題を追加

会話開始後の「次の自分側ターンで話題を送る」で、新しい話題を1件予約できます。現在の生成や送信は中断せず、次の自分側の番で「話題を変えよう。」に続けて入力文を送ります。
この文自体が通常のモールス本文として同じリンクを通り、1ターンを使います。相手のAIにテキストを直接注入する裏経路ではありません。表示は「あなたの話題変更」としてAI生成と区別します。相手から受信確認が来るまでは到達したとは扱いません。
1台試用の場合はA側への予約です。残りの自分側ターンがなければ予約できません。予約取消・すべて停止で未送信の話題を破棄します。既定180 UTF-8バイトの上限は、案内文も含めて適用します。

## 会話が途切れにくい制御

相手の質問に答え、理由・例・質問のいずれかを加えるよう促します。挨拶だけ、空文、自分の過去発言の反復、文字数超過は送信前に簡易検査します。問題時は実モデルに一度だけ再生成させ、再度失敗すると停止します。未検査の文、固定の代替返答、途中で切った文は送りません。
この検査は意味理解や事実確認の完全な評価ではありません。意味の近い反復や話題の逸脱を必ず検出するわけではなく、再生成は追加の推論時間を使います。端末・モデルによって自然さや速度は異なります。
履歴は正確な最近の発言に限定し、最大12件・約4000 UTF-8バイトの範囲へ整理します。古い会話は省き、覚えているふりをする要約は作りません。通常はシステム文と履歴の完全一致が続くためネイティブKV再利用が可能ですが、履歴の窓更新・再生成後はキャッシュを再構築する場合があります。

## 維持する制限

会話の既定は8ターン、設定可能範囲は2〜32。勝手な無制限実行はしません。通信の本文・暗号形式はMT2/MTO1と互換です。音響ではスピーカー・マイク、オンラインでは暗号化した点・線の列を送り、オンラインの中継サーバーは引き続き別途必要です。新たな公開サーバーの設置は行いません。
画面非表示で停止し、受信文を設定権限やコマンドとして実行しません。診断ログは既定で会話本文を除き、人の話題変更も含めるには明示的な本文保存許可が必要です。

## 再現試験

```
node scripts/build.mjs
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py' -v
python tools/test_conversation_ui.py
# 実モデルを用意したCI/開発環境のみ:
bash tools/start_ci_model.sh
python tools/test_conversation_topics.py
```

実モデル試験は10話題×4ターン、追加の3スタイル×4ターン、人の話題変更を含む6ターンを実行して、生の応答と完全一致・受信確認を保存します。PCMは数値計算であり、実時間音声や実機2台の結果ではありません。会話内容の自然さ・事実性は全文を別途レビューします。スクリプトの追加自体はモデル試験成功を意味しません。
